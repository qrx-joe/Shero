## 第 3 页 | 产品定位

**标题（中文）：**
02 产品定位：门外风险的"可移动安全探针"

**标题（英文）：**
Product Positioning: A Movable Safety Probe for Doorway Risks

**正文：**
**核心命题：**
把"开门确认"的人身风险，转移给可移动、可回传、可控的机器人。

**三条边界：**

| 边界 | 说明 |
|------|------|
| **不追人、不靠近陌生人** | 机器狗只负责门外观察，最终决策权始终在用户 |
| **不承诺绝对安全** | 只报告"画面中未观察到明显人员停留"，不说"确认安全" |
| **用户掌握回收时机** | 巡视完成后停在门外，用户确认情况后再触发返回 |

**演讲者备注：**
- 三条边界用三个色块或图标突出，不要大段文字
- "不承诺绝对安全"这一条要特别醒目，这是可信度来源
- 不要出现"自动判断危险""自动追踪"等词汇

## 第 4 页 | MVP 闭环（严格对齐代码）

**标题（中文）：**
03 MVP 闭环：固定路线出门 → 停留回传 → 用户确认 → 安全返回

**标题（英文）：**
MVP Closed Loop: Fixed Route Patrol → Hold & Stream → User Confirm → Safe Return

**正文（流程图形式）：**

```
[用户点击"出门巡视"]
    ↓
[机器狗从 A 点出发]
    ↓ 固定路线
[B 点] → [C 点] → [D 点]
    ↓
[停在 D 点，Rerun 持续回传画面]
    ↓
[用户在门内确认当前情况]
    ↓
[用户点击"巡视后回家"]
    ↓
[机器狗按返回路线回到 A 点]
    ↓
[任务完成]
```

**关键参数：**
- 观察范围：门边 1-2 米
- 运动方式：固定路线 A-B-C-D，非自主导航
- 速度：低速（前进 ≤ 0.35 m/s）
- 回收方式：用户触发，非自动返回

**演讲者备注：**
- ⚠️ **这是最关键的一页，必须和代码完全一致**
- 不要出现：人像识别、自动停止、30秒复检、截图报告、自动返回
- 用流程图或时间轴展示，不要大段文字
- A-B-C-D 路线建议配一张简单的俯视图

## 第 6 页 | 技术取舍

**标题（中文）：**
05 技术取舍：不追求复杂导航，先把可控闭环跑稳

**标题（英文）：**
Technical Trade-offs: Stability Over Complexity

**正文（三层结构）：**

**第一，固定路线。**
基于 DimOS + Unitree Go2，定义 A-B-C-D 固定动作序列。不是自主导航，是把"不确定的门外环境"变成"可预知的固定动作"。

**第二，安全锁。**
- 默认 dry-run，预览动作但不执行
- 必须显式 `--armed` 才发布真实运动指令
- 速度硬上限：前进 ≤ 0.35 m/s，转向 ≤ 0.8 rad/s
- 随时可中断，零速度安全停止

**第三，可视回传。**
Rerun 接入摄像头和点云画面，高带宽流走共享内存传输，保证现场演示画面不卡。

**演讲者备注：**
- 三层用三个卡片/色块展示，不要堆在一起
- "安全锁"是亮点，dry-run / --armed 这组词要突出
- 可以配一张 DimOS → Go2 → Rerun 的简单架构图
- 不要提 SecurityModule / YOLO / EdgeTAM / FOLLOWING

## 第 7 页 | 差异化

**标题（中文）：**
06 差异化：从"被动监控"到"主动探查"

**标题（英文）：**
Differentiation: From Passive Monitoring to Active Probing

**正文（三列对比）：**

| 智能门铃/猫眼 | 家用摄像头 | 我们的机器狗 |
|---|---|---|
| 固定视角 | 室内监测 | **可移动到盲区** |
| 无法看拐角 | 无法出门 | **替用户完成暴露动作** |
| 被动等待 | 被动记录 | **主动探查 + 停留回传** |

**核心差异：**
移动视角 · 风险替身 · 可控探查

**关键句：**
> 我们不是在卖一台机器狗，而是在做"开门前的安全确定性"。

**演讲者备注：**
- 三列对比是最有效的展示方式
- "风险替身"这个词要保留，它是产品灵魂
- 不要出现"异常留证""复检闭环"（MVP里没有）
